# WorkProof Blender 插件

需要 Blender 4.2+ 与已启动的 WorkProof 桌面引擎。无额外 Python 依赖，自动发现本地引擎。

从 GitHub Actions 下载 `workproof-blender-extension` 产物并解压外层 ZIP。在 Blender 的「偏好设置 → 获取扩展 → 从磁盘安装」选择其中的 `workproof-blender-0.3.0.zip`，开启扩展后，在 3D 视图侧栏找到 WorkProof。先保存工程，再点击开始记录。完成后点击保存并导出。`.wproof` 保存在工程旁边，与 `.blend` 一起核验。

采集网格顶点/边/面数、对象数、修改器数、网格变化信号、撤销/重做、保存、暂停与恢复。采集器不保存几何坐标、网格内容或对象名称；导出时本机引擎读取最终工程计算摘要。依赖图回调只标记脏状态，至多每秒采样一次。网络放到有限队列的后台线程，不在 bpy 回调内执行网络请求。

对象结构增量：开始、脏状态采样和继续时，内存中读取对象父级、对象/数据临时标识、世界变换矩阵及修改器临时标识、类型、顺序和显示开关，仅将带版本域的 SHA-256 摘要写入 checkpoint。事件链和工程摘要仍由 Rust 引擎使用 BLAKE3；结构摘要不会被标注为 BLAKE3。原始对象名称、修改器名称、矩阵和标识不会发送。最多 50000 对象、200000 修改器，序列化输入最多 16 MB，出现超限或无效数值时暂停，不把未知状态当作完整记录。

摘要能够区分数量不变时的父级变化、变换和同类型修改器重排，但不能恢复结构树、逐操作分支或精确参数变化。临时指针只用于当前 Blender 会话中的状态区分，不是跨重启稳定身份。相同数量的网格坐标修改仍仅表现为网格变化信号；本增量不读取几何坐标来形成结构摘要。视口旋转和缩放使用独立的计数采样，不保留视口坐标；逐笔压感和精确修改器参数演进尚未采集。暂停和断连会暴露缺口。插件卸载或工程切换会结束当前记录，未导出的内存队列不会成为证书。

宿主操作系统和 Blender 本身可能要求确认扩展加载或网络权限。Actions 将交付 ZIP 安装到全新的 Blender 用户目录，重启后检查扩展已启用，并使用该扩展记录、导出和核验工程。产物中的 `test-blender-results.json` 给出所测 Blender 版本和 ZIP 的 SHA-256。桌面图形界面中的安装与操作仍需按宿主版本验收。
