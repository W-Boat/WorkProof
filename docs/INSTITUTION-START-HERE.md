# 机构版从这里开始

机构版让老师或项目负责人集中保存、核验创作证书，并按需使用辅助分析。它与用户电脑上的记录软件分开部署：服务器不需要为每位创作者持续运行 Word，也不会代替本地创作记录。

## 先决定需要什么

| 你的需求 | 需要准备的内容 | 用户能做什么 |
|---|---|---|
| 登录工作台、查看核验结果 | 基础机构服务器包、Docker 和数据库/缓存镜像 | 使用机构网页和已有账号权限 |
| 保存证书、查询记录 | 基础服务完成后，由管理员明确准备证书目录 | 保存、去重、查询、筛选和导出 |
| 批量核验、重启后继续处理 | 先准备证书目录，再准备持久任务 | 创建和提交批量核验任务；临时上传残留不会自动提交 |
| 分析文本中的 AI 线索 | 匹配版本的可选 CPU 运行环境、管理员选定的模型 | 用户选择文件、选择模型、明确同意发送后分析 |

基础服务器包不包含检测模型。三个模型也不代表三种独立算法：MPU 中英文和 Desklib 英文均属于监督分类。另一个现代模型 LRR 方法目前只在独立实验中评估，尚未接入正式工作台。

## 第一次部署

1. 从同一源码版本的成功 Actions 领取基础包，核对外层下载摘要、包内 `SHA256SUMS.txt`、`BUILD-INFO.json` 中的源码和平台。不要把不同版本的控制工具和镜像混用。
2. 在专用目录解压，按[基础服务器说明](INSTITUTION-SERVER.md)加载预构建镜像并准备数据库/缓存镜像。无需在本机编译应用。
3. 使用包内工具生成这个部署专用的随机账号和秘密，再明确初始化全新空数据库。完成后启动服务并登录。已有数据库应保留，不通过重新初始化修复问题。
4. 需要目录或批量功能时，分别按服务器说明进行准备。管理员工具先完成停服加密备份，再执行所选准备；成功后仍由管理员明确启动。
5. 需要 AI 辅助分析时，再按[可选 AI 说明](INSTITUTION-AI-DEPLOYMENT.md)准备匹配的运行环境和模型。普通启动不下载或自动启用模型。

这里没有通用账号密码。每个新部署的账号由自己的准备工具生成，通过包内账号工具领取；不要把账号、数据库秘密或备份口令放进命令参数、项目源码或公开日志。

## 已有部署怎么处理

先记录当前源码、镜像和部署目录，再备份。新版本在云端通过检查，不代表已安装到你的服务器；下载的新包也不会自动替换运行中的服务。当前没有验证所有历史版本之间的自动升级，不能直接套用全新空库的初始化步骤。

恢复工具把经过认证的备份放进全新项目，保留源部署。恢复成功后服务保持停止，管理员明确启动并用原账号登录。目录与持久任务需要通过对应的记录、结构和输入核验；AI 默认关闭。

同一主机上保留了原模型卷时，可用明确的复核工具重新启用 AI：指定原卷归属、原镜像、源码提交、新备份和新配置输出。复核只读检查原记录和模型，再运行离线合成输入；成功不改原记录、不启动应用。把权重迁移到另一台主机的完整流程仍未验证。

## 目前哪些结果有证据

- 基础服务、证书目录、持久任务、备份和新项目恢复已有 Linux amd64 Docker 验收，具体范围见[基础包记录](INSTITUTION-DELIVERY-6592819.md)。
- 三种模型的准备、真实接口检测、取消清理、恢复默认关闭、恢复项目重新启用，以及候选运行环境打包，已在[任务 41626918967](https://github.com/W-Boat/WorkProof/actions/runs/41626918967)全部通过。中文候选包完整下载及全部包内摘要已核对，见[交付记录](INSTITUTION-AI-DELIVERY-cf1ab54.md)；它必须匹配同源码基础镜像，未安装到现有部署。英文两个候选包尚未完成本地下载核验。
- 实际中英文模型误报见[独立评估](AI-CALIBRATION-RESULTS.md)。LRR 的[独立中英文评估](https://github.com/W-Boat/WorkProof/actions/runs/41628627615)仍在运行，运行速度通过检查不代表识别准确。

分析结果只是辅助线索，应与创作过程、来源和人工复核一起使用，不能由分数单独认定作弊。商业分发仍需遵守[逐项许可审查](COMMERCIAL-LICENSE-AUDIT.md)中记录的条件和未解决项。

服务器说明中的早期“待实现”“待验收”段落保留了历史背景；判断当前可用范围时，应以对应源码和具体任务的成功记录为准。
