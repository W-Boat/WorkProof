默认机构镜像和 Rust 创作记录进程不包含 Torch 或模型。可选 CPU 镜像基于同版本机构镜像，继续使用已有的 Java 权限、明确发送同意、单任务进程、120 秒期限、取消及私有输入清理，不另建一套分析协议。

管理员需明确选择模型，运行 `prepare_ai.py` 并同时指定 `--allow-model-download` 和 `--synthetic-self-test`。该工具要求已停止且镜像身份匹配的部署，在修改配置前完成加密备份；已有模型卷、准备记录、未完成标记或输出文件一律拒绝覆盖。在线助手只挂载新模型卷，不读取应用配置或待分析文档。下载使用现有固定引擎版本，随后切换到无网络的独立助手，以服务用户运行合成文字推理；这检查加载与协议，不证明准确率。

私有 `ai.json` 保存运行时、模型版本和完整文件摘要。源部署专用 override 固定 AI 镜像、只读挂载模型，并设置显式激活标记；普通启动不下载模型，也不只凭目录存在启用分析。模型卷多出未选择的引擎、文件被修改、链接或权限不符时拒绝激活。

常规加密快照保存严格验证的 AI 记录，不包含模型权重。恢复使用默认 Compose，不继承源 override 或激活标记，因此 AI 保持关闭。不能通过删除记录强行重放准备，也不能把恢复成功当作 AI 已就绪。

`reactivate_ai.py` 已补充源码，尚未通过真实服务验收。管理员需显式指定已准备的原模型卷及其所属项目、原基础镜像和 AI 镜像完整 ID、源码提交、新备份和新 override 路径，并选择 `--synthetic-self-test`。它要求应用停止，先做加密备份，然后在无网络助手中只读挂载配置和模型，逐文件复核并以服务身份运行合成文字推理；成功只生成新的私有 override，保留原 `ai.json` 字节、模型文件和停止状态。已存在的 override、模型篡改、镜像不符、未完成准备标记或卷归属不符均拒绝。

同一 Docker 主机上的恢复项目可以显式指定仍存在的源项目模型卷；这不迁移权重，也不支持把未知目录作为已准备的模型卷接入。目前新增验收覆盖计划是原项目复核后再次启用、原记录字节不变、拒绝覆盖和篡改拒绝；恢复项目复核后的完整验收仍需补齐。

独立 `institution-ai.yml` 需要成功的基础机构任务编号和完整源码提交。它核对任务身份、GitHub artifact 摘要、包内清单、镜像来源/平台和依赖仓库摘要，构建可选 CPU 层，然后按显式选择运行三种引擎的真实服务验收。本地不执行构建、模型下载或推理。

当前 MPU 中英文和 Desklib 英文都属于监督分类方法。离线标志不是应用容器的网络沙箱，应用仍需访问数据库和缓存；模型及基础模型、运行时依赖和商业分发许可缺口未因此解决。真实误报和范围见[独立评估](AI-CALIBRATION-RESULTS.md)，不能单独用于认定作弊、身份或 AI 内容比例。
