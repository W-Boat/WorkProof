# 用户操作与界面用语

WorkProof 的操作应当先说清楚“现在做什么”，再说明结果。内部实现名称放在文档或可展开详情中，不让普通用户先理解算法、接口或数据库术语。

## 桌面工作台

先选择创作软件，再显示该软件的三个步骤。默认 Word，随后为 WPS。完成操作后的连接管理、记录数量放在后面；待确认的新连接请求仍显示在前面，避免错过确认。

只在选择 VS Code 时显示它的安装按钮。Word、WPS、Photoshop 尚未完成的安装入口直接说明现状；“有适配代码”和“普通用户能一键安装”分开判断。

## Word/WPS 面板

1. 点击开始，在 WorkProof 窗口核对并允许连接。
2. 正常编辑，需要休息时暂停。
3. 导出作品和证书，把这两个文件一起发送。

开始、暂停、导出一次只处理一项。等待连接或生成证书时禁用其他操作；已开始的后台读取、保存会先完成。重复点击不会创建额外连接或重复下载。

错误说明包含下一步。例如，切换文档后提示重新打开面板，为新文档开始记录；连接失效后明确暂停，提示重新允许连接；未保存到本机服务的操作不会混进新记录。

## 统一用语

| 内部说法 | 默认界面用语 |
|---|---|
| 宿主 | 你使用的软件 |
| 持久化事件 | 已保存的操作 |
| 本地引擎就绪 | WorkProof 已就绪，可以开始记录 |
| 交付件 | 作品 |
| 活动文档已改变 | 你已切换到另一份文档 |
| 采集缺口 | 这段未记录的时间 |
| 原生授权 | 允许连接；另外说明插件发布者尚未确认 |

文档与原始核验详情可保留技术名词，供审计和开发使用。简化用语不改变实际权限：允许插件通过 WorkProof 提交和导出自己的记录，不意味着控制或撤销它在宿主软件中已有的文件访问权限。

## 证书与可信程度

图片用于展示，复核需要原作品和 `.wproof`。指纹用于与可信渠道取得的证书对照；自签名不证明作者身份、原创性或 AI 使用比例。部分记录与完整记录的核验范围必须明确区分。

机构检查弹窗按选择文件、确认发送范围、查看结果分组；按钮不能使用时解释下一步。独立核验页的明细按每项实际结果显示说明：作品不匹配时提示索取对应作品，记录或签名不一致时提示索取原始证书，失败项不得继续写“内容一致”。这轮增量仍待对应 Actions 验收。

本轮验收为 [完整 Actions 41269692613](https://github.com/W-Boat/WorkProof/actions/runs/41269692613)：28 项浏览器测试覆盖首屏顺序、软件切换、重复点击、文档切换、授权失效与导出。Word/WPS 接口和 Tauri IPC 在这些浏览器用例中是模拟；真实宿主与新用户首次安装仍须继续验收。
