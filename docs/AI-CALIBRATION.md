# 分开校准与保留集评估

DetectorScope 新取样已通过 [42752004347](https://github.com/W-Boat/WorkProof/actions/runs/42752004347)，完整选择记录及 artifact 摘要见[冻结证据](evidence/detectorscope-selection-70beaf5/acceptance.md)。新增独立评分工作流（待 Actions）在中英文两任务中重建同一清单、核对原始及 float16 派生权重，再按 8–512 token 明确拒绝超限输入。校准每类须至少 100 条已评分且总覆盖至少 90%，否则不生成阈值；以校准人工误报预算 5% 选定 logit 阈值并独占落盘后才评分留出集。普通工作台仍不启用该引擎，部分报告不是已验证效果结论。

DetectorScope 独立真实取样流程已提交（待 Actions）：在核验完整 DetectRL-X 固定文件后，使用 `workproof-detectorscope-calibration-v1` 命名空间，排除 13 份既有报告中的所有输入及命中的原人工文本分组，每语言/分区固定 384 份样本（人工、AI 各 192）。96 个分层单元不足时拒绝，不根据模型分数或 token 长度挑样。原文只保存在 runner 私有临时目录，附件仅包含 ID、标签、来源类别和摘要；本轮不加载模型或评分。正式效果评估必须核对该冻结清单，不允许改选困难样本或悄悄截断超限文本。

新方法的已观察样本排除底座（新增，待 Actions）：`observed_samples.py` 使用[固定索引](research/detectorscope-prior-sample-index.json)核对 13 份既有报告的原始文件摘要及 4,416 条记录数量，收录首轮基准、三个分类器的校准/留出报告和 LRR 中英文校准/留出报告。所有状态的有效输入摘要均排除，不依据分数筛选。文件缺失、变更、数量不符或摘要无效时拒绝继续；索引不包含原文。此处只建立排除集合，尚未选择或冻结新的真实样本，也不能证明没有语义重复、同源关联或训练集污染。

新增实验准备（待 Actions）：取样底座允许显式命名空间，旧流程默认仍为 `workproof-calibration-v1`，保持原结果。DetectorScope 合成取样检查使用独立命名空间，并排除旧选择的全部摘要，验证确定性、同源分组、分区不交叉及无效命名拒绝。这不代表新的真实数据集已准备，更不代表已评估误报。正式新评估仍须汇总此前所有已观察报告的摘要、冻结完整样本清单后再推理。

这套流程先用一批样本确定阈值，再用另一批事先留出的样本衡量误报与漏报。两批文字在推理前一起选定；确定阈值时不读取保留集分数。流程已经实现，但实现完成、fixture 通过或任务开始运行，都不能作为检测效果的结论。实际指标须以完整的保留集报告为准。

## 为什么重新取样

[第一轮公开基准](AI-BENCHMARK.md)使用上游固定规则，每语言包含 192 份样本。那一轮的结果已经被查看，不能再把同一批文字称为未查看的保留集，也不能一边根据它调阈值，一边用它证明效果。

新流程读取 `docs/evidence/ai-benchmark-50b4463` 中三个模型报告的全部样本摘要，包含未成功评分的样本。任一人工文字或生成文字的摘要命中第一轮记录，就排除对应文字对，并排除共享同一原始人工文字的其他候选。三个报告都必须存在且通过校验，不能在缺少排除记录时继续。

## 两批样本怎样固定

使用与第一轮相同的 DetectRL-X 来源：revision `ccc9a0a74793dd3448e0da1650b430f5df1b0402`，文件 `Binary/binary_general_256_open.json`，大小 775,337,623 字节，SHA256 为 `9b3fe5250b85ee02749282600a803c843e0205e0c411dea8460bea6eb21262ff`。下载后先核对完整文件大小与摘要，再解析。只使用上游 test 分区中的中英文记录；这里的“校准集”和“保留集”是本项目在这份来源内重新划分的用途，不是上游提供的独立训练集与测试集。

`calibration_data.py` 先对原始人工文字计算 SHA256，再按带固定前缀的摘要奇偶分配用途。同一原始人工文字在不同生成器下出现时，所有对应文字对只能属于同一用途，不能跨到另一批。

每批继续按语言、生成器和领域分层。四个生成器为 DeepSeek-V3、Gemini-2.5-Flash、GPT-4o、Qwen-Max，领域为来源中的六类。工作流固定每格 8 对人工/生成文字，因此每语言、每批均为 192 份人工与 192 份生成文字，共 384 份。两种语言、两批合计 1,536 份文字。

格内按内容摘要排序，使用有界候选池，再做全局精确文字去重。整个选择过程不读取检测分数，也不按模型 token 数挑选容易处理的样本。空文字、超过 32,768 UTF-8 字节的文字对和人工/生成文字完全相同的文字对不会入选。候选不足、配额不足、来源总行数不符或不足 96 个分层格时停止，不能静默降低样本量。正文按原始字节保留，检测器遇到长度限制时应拒绝处理，不能截断后当作完整样本评分。

两批 JSONL、样本摘要清单和选择收据在任何推理之前一起生成。收据记录来源、排除记录、格内计数和两批文件摘要。每个模型任务独立重建同一批固定输入，原文留在 Actions 临时目录。

## 阈值怎样确定

MPU 英文、MPU 中文和 Desklib 英文分别运行，各自使用注册表中的固定模型版本。先加载上游策略，对校准集评分，生成 `calibration-report.json`；这一步保留连续分数，后续选择阈值只使用校准集分数。

`calibrate.py` 要求人工与生成样本各至少有 100 份成功评分，总成功覆盖率至少 90%。允许记录不支持或输入不足；出现错误、超时等推理失败时不能生成策略。全部校准样本摘要还要与保留集摘要逐一检查，不允许精确重叠。

工作流预先声明的人工误报预算为 5%。程序按 `score >= threshold` 判为 AI，从候选阈值中选出满足校准集人工误报比例不超过 5% 的最低阈值；生成样本的分数用于记录校准漏报情况，不参与这一阈值目标。没有可行阈值时停止。

5% 是这批已成功评分人工样本上的经验预算，不能解读为真实用户误报率上限，也不是统计置信保证。冻结策略记录阈值、模型版本、校准文件摘要、全部校准输入摘要、保留集清单摘要和实际评分数量，策略模式为 `independent_calibration`。

## 保留集报告怎样阅读

策略冻结后，工作流才对对应语言的保留集运行一次评估，不使用保留集分数重新选择阈值。若以后根据这次保留集结果修改规则，就应另找新的未查看样本验证，不能继续把它当作未触碰的最终评估。

`heldout-report.json` 报告实际覆盖、未完成状态、人工误报、生成漏报及 Wilson 95% 区间，并提供分组结果。384 是预先选定的总记录数，不保证全部都能成功评分。误报与漏报须连同各自成功评分分母一起阅读；未完成样本不算判对，也不等于“没有 AI”。

工作流检查总记录数为 384、人工与生成的指标分母均大于零，并拒绝 `error`、`timeout`、`not_configured` 状态。它没有设“准确率达标”门槛。因此任务成功表示运行与报告检查完成，不能直接解释为误报足够低、漏报可接受或可以上线。

## 运行与证据

[工作流](../.github/workflows/ai-calibration.yml)在该工作流文件变更时启动，也支持手动 dispatch。全部 fixture、模型下载与推理交给 Linux GitHub Actions，本地不运行测试或模型。

每个模型归档 `separate-calibration-<engine>`，内容包括选择收据、对应语言的两份摘要清单、上游策略、模型收据、校准报告、冻结策略和保留集报告。上传步骤即使失败也会执行，所以拿到部分产物不代表整套评估已经完成。必须检查任务状态与文件完整性，再引用结果。原始数据、选中文字和模型权重不作为公开产物上传。

相关实现为 [calibration_data.py](../tools/ai-assessment/calibration_data.py)、[calibrate.py](../tools/ai-assessment/calibrate.py) 和 [evaluate.py](../tools/ai-assessment/evaluate.py)。fixture 只验证选择、阈值冻结及指标计算的程序约束，不证明数据标签正确或模型有效。

## 目前能说明的范围

这套划分保证的是原始人工文字分组和精确文字摘要层面的分离。它没有证明模型训练时没有见过这些文字，也没有排除跨批语义近重复、共享提示词、共同原始文档或其他关联。样本可能相关，Wilson 区间采用的独立性假设因此可能偏乐观。

范围仍限于 general_256 变体、四个来源生成器和中英文；不能据此推广到完整论文、所有近期模型、改写、翻译、混合写作或真实学生作业。上游的人类标签、生成来源和原始语料权利尚未独立核实；数据卡的 MIT 声明不等于完整商业使用许可已经核清。来源声明见[固定数据卡](https://huggingface.co/datasets/WUJUNCHAO/DetectRL-X/blob/ccc9a0a74793dd3448e0da1650b430f5df1b0402/README.md)。

本页说明已实现的协议，不填入尚未核查的运行指标，也不据此承诺误报目标或生产可用性。
