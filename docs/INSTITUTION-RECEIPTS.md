# 机构接收回执使用说明

接收回执回答的是：持有某把机构私钥的服务，是否接收过这份完全相同的证书。它不证明作者身份，也不证明创作过程一定真实。客户端自己的签名与机构回执是两件事，接收方应分别核对。

## 管理员如何使用

1. 登录机构工作台，点击“签发接收回执”。只有具备 `workproof:receipt:issue` 权限的账号才显示入口；后端也会检查权限。目前尚未提供普通角色的菜单授权条目，不能将入口显示视为所有角色均已接入。
2. 选择创作者导出的原始 `.wproof` 文件，阅读发送范围并勾选同意。作品文件不会随此操作上传，证书本身可能含文件名、记录时间和操作数量。
3. 点击“发送并签发回执”。服务检查证书内容，签发后点击“下载接收回执”。此接口不保存完整证书，也没有提供回执列表或补领接口。
4. 将原始证书和回执 JSON 一起交给接收方。不要重新保存、排版或改写原始证书，哪怕只改变空格，也会使它与回执不再匹配。

关闭窗口只取消等待。服务器可能已经完成签发，因此不能把取消等待理解为撤销回执；重复提交可能产生不同的回执编号。

## 接收方如何检查

1. 在核验网页中先检查作品与原始 `.wproof` 证书。
2. 展开“核对签发者与接收回执”，选择回执文件。
3. 通过机构官网、机构管理员的已核实联系方式等独立可信渠道，取得签发者编号和公钥文件。不能仅相信随回执一同发来的陌生公钥。
4. 选择公钥文件，填写机构签发者编号，确认已经核对公钥来源，再开始核验。

浏览器本地 Wasm 检查机构签名、证书原始字节、分享范围和有效期，不上传这些文件。通过后表示回执与本次证据一致，并不把“官方客户端来源”或“作者身份”改为已认证。完整证书和只分享部分记录的证书不能互换回执。

有效期检查依赖接收设备当前时间，接收时间由签发服务器声明。这不是独立可信时间戳，也不包含在线吊销查询。

## 服务准备范围

当前接口默认关闭；无需为查看工作台自动生成任何机构密钥。运行真实 JAR 的部署方需自行准备经过审核的 `workproof-receipt` 工具、独立机构 Ed25519 密钥及可信公钥发布渠道，再提供以下配置：

- `WORKPROOF_RECEIPT_EXECUTABLE`：工具绝对路径，文件名为 `workproof-receipt` 或 `workproof-receipt.exe`。
- `WORKPROOF_RECEIPT_PRIVATE_KEY`：私有种子文件的绝对路径，内容为 32 字节种子的 64 位十六进制文本。它不是 PEM 或 PKCS#8 文件，也不是 64 字节扩展私钥。禁止放入客户端安装包、源码或普通日志。
- `WORKPROOF_RECEIPT_PUBLIC_KEY`：独立配置的公钥文件绝对路径，内容为 32 字节公钥的 64 位十六进制文本。签发工具会核对这把公钥与私钥是否匹配。
- `WORKPROOF_RECEIPT_ISSUER_ID`：机构用于独立核验的固定 ASCII 签发者编号。
- `WORKPROOF_RECEIPT_LIFETIME_SECONDS`：有效期秒数，默认 86400，允许 1 至 2678400 秒。浏览器核验最大允许 31 天。

私钥文件必须属于运行服务的账号：POSIX 权限严格为 `0600`；Windows ACL 仅授予运行服务的主体。服务拒绝符号链接和不合要求的文件，不会自动修复权限。接收回执原生进程输入最多 32 MiB、输出最多 16 KiB，每个签发工具实例最多两并发，原生处理期限 15 秒；部署方仍需为 HTTP 上传设置超时和访问频率限制。

本次源码已将签发工具加入 Linux amd64 镜像和基线 JAR 附件，并把本说明加入服务器归档；新增镜像工具验收仍待 Actions，不能据此替换此前未含工具的包。默认 Compose 不传递签发配置，也不挂载机构密钥，因此签发仍关闭。显式密钥启用和带配置的镜像 HTTP 签发还需单独验收，不能仅凭工具存在宣称生产部署完成。密钥轮换、托管、吊销、回执索引、客户端远程证明仍待建设。请先在隔离环境用测试机构密钥验证，再决定生产部署。

## 验收证据

### 显式 Compose 附加配置（新增，待 Actions）

后续增加实际外部挂载验收：使用这份附加配置启动独立只读应用，以新建私有目录中的合成密钥检查 HTTP 签发、独立核验、容器修改文件拒绝和宿主更换公钥后的拒绝。该新增场景尚待 Actions，不代替生产密钥备份恢复验收。

新增 `compose.receipts.yaml` 与包内 `compose.yaml` 配合使用。它要求明确设置 `WORKPROOF_RECEIPT_ISSUER_ID` 和 `WORKPROOF_RECEIPT_KEY_DIRECTORY`，后者必须是已存在的绝对路径目录，包含 `seed.hex` 和 `public.hex`。目录必须允许容器 UID 10001 读取，私钥仍须属于该账号且为 `0600`；不得因此开放目录或私钥给其他用户。配置不创建目录、不生成密钥，只将目录只读挂载到 `/private/receipts`。有效期可用 `WORKPROOF_RECEIPT_LIFETIME_SECONDS` 设置。

在完成独立密钥备份与权限核对后，管理员可在专用部署目录显式使用 `docker compose -f compose.yaml -f compose.receipts.yaml config` 预检，再自行安排维护窗口启用。此附加文件不会由普通启动自动读取。当前新增验收只检查 Compose 配置解析，实际同路径只读外部密钥挂载与备份协调器兼容性尚待集成验证；不能据此称为点击即用的生产部署。

**外部密钥不在普通 WorkProof 加密备份中。** 现有备份协调器有严格挂载身份检查，启用此附加挂载后可能拒绝备份；不要绕过检查。恢复默认不带此附加配置，也不会自动恢复签发身份。生产启用前必须完成外部密钥备份、恢复与协调器集成验证。勿把签发密钥放入原配置卷以试图让旧备份收录它，未知文件会被拒绝。
