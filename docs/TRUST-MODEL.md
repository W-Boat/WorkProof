# WorkProof 来源、采集与规则信任边界

## 当前实现

原协议清单使用 `identity=self-signed`，本机生成并保存签名密钥。独立核验检查作品指纹、记录链、Merkle 归属及签名；证书内的公钥不能自行证明官方来源。攻击者可以生成自己的密钥并构造自洽记录，或者在获得本机密钥后签署构造的数据。现有功能不构成官方客户端运行证明。

核验页分别显示文件与签名、官方客户端来源、采集过程真实性和过程规则有效性。没有来源凭据时保持“未认证”，没有独立采集证明时保持“未独立验证”；不得从签名通过、文件名、品牌图标、来源字符串或事件数量推导官方身份。规则版本是可追溯标识，不是准确率认证。

## 后续实现要求，尚未交付

1. 官方软件发布应有独立信任渠道、安装包代码签名和可核验构建来源。安装包来源认证与证据内容真实性分别处理。不得将官方签发私钥嵌入客户端、插件、网页、仓库或示例配置。
2. 官方或机构签发服务由独立配置的签发密钥签署接收回执。回执至少绑定原始 WorkProof 签名摘要、最终作品指纹、会话、记录链头、设备公钥、接收时间及签发策略版本。保留原 `.wproof`，附加凭据单独核验。验证者通过独立配置取得受信任公钥，不能因为输入文件自带根证书就接受它。
3. 仅收到一份文件后补签只能表示“该服务接收过这些数据”。加强过程保证需实时随机挑战、会话与序号绑定、分批摘要提交、重放与分叉拒绝、设备注销和密钥吊销。服务端时间不能被本机声称的时间替代。事后提交不得冒充实时接收。
4. 每台设备使用独立密钥；硬件不可导出密钥能降低私钥复制风险，但不自动证明调用程序或操作内容真实。只有结合可验证的运行环境测量、可信参考值和远程证明策略，才能提升客户端来源保证。未支持的平台应降低保证范围，不能返回虚构的证明结果。
5. 来源、接收、运行环境与行为规则结论分别展示。设备注册成功不能直接显示“官方客户端生成”；收到日志不能直接显示“真实操作”；通过远程证明也不能直接显示“人类亲手完成”。

当前没有配置生产官方签发密钥、公开可信根、吊销服务或硬件远程证明策略，因此不得将测试 CA 或合成回执称为官方认证。参考 [IETF RATS 架构](https://www.rfc-editor.org/rfc/rfc9334.html)。

## 服务器接收回执底层 API

`crates/proof/src/receipt.rs` 提供 `issue_receipt` 和 `verify_receipt`，格式为 `workproof-server-receipt/1`，用途固定为 `server-received`。回执独立于原始证书，Ed25519 签名使用固定领域分隔前缀和按结构字段顺序序列化的 UTF-8 JSON；不能以任意 JSON 字节或其他协议签名替代。外层和负载均拒绝未知字段。

负载绑定收到的证书原始字节的 BLAKE3 摘要、原签名、作品声明指纹、会话、实际披露范围与数量、签发者标识、回执编号及服务端接收/失效时间。即使只对原证书增加空白，回执也不再匹配；请保留原件字节，不重新序列化后冒充原件。当前不将完整证书回执转用于字节不同的选择性披露文件。

核验者显式传入期望签发者标识、公钥、当前时间和最大允许有效期；回执不含可自动信任的公钥。错误公钥、过期、未来、过长有效期、修改签名或负载、其他证书和伪造用途均拒绝。时间政策依赖调用者选择可信时钟；这不是独立 TSA 时间证明。

成功只设置回执验证和配置公钥匹配，不设置作品已检查、官方客户端来源、采集真实、作者身份或规则校准已认证。该库尚未接入机构签发接口、可信根发布、密钥轮换、吊销、数据库回执编号唯一性或浏览器导入，因此核验页继续显示官方来源未认证。接收回执可随证据重复展示；实时挑战和防重放状态机尚未实现，不得以静态回执代替。

源码 `08930397c495e7edd64f5fd4e8f41e800d53ac5e` 的 [回执协议专项 42349928106](https://github.com/W-Boat/WorkProof/actions/runs/42349928106) 已成功，43 项 Rust 协议检查及 1 项文档测试通过。新增检查覆盖显式可信公钥、错误公钥与签发者、篡改、过期/未来/超长有效期、字节不同但仍合法的证书、无效输入、未知字段及用途冒充。合成密钥只存在于测试，不是生产官方信任根；该结果不包含服务器接口或硬件证明验收。

### 一次性签发与核验工具

`workproof-receipt` 使用上述共享 Rust 实现，供机构后台后续受控调用；不启动记录服务，不读取客户端默认密钥，不创建密钥、不访问网络。密钥参数必须为绝对路径，文件内容为 32 字节种子或公钥的 64 位十六进制字符串。私钥文件只供受控服务进程读取，不把私钥值放到命令行或输出。

```text
workproof-receipt issue original.wproof receipt.json institution-id 86400 /secure/issuer-private.hex
workproof-receipt verify original.wproof receipt.json institution-id 86400 /independent/issuer-public.hex
```

`issue` 在本进程读取系统时间、生成随机 256 位回执编号，校验证书内部一致性后写入全新的回执文件。有效期参数单位为秒，限制 1 秒至 31 天；接收时间不从证书或用户参数复制。已有输出拒绝覆盖，原证书不变。文件写入失败可能留下不完整的新文件，后续核验会拒绝，工具不会擅自覆盖重试。

`verify` 使用独立提供的公钥、期望机构标识、系统当前时间及最大允许有效期。成功仍明确输出实际作品未检查、官方客户端来源未认证、操作真实未验证、作者身份未认证、规则校准未认证。受控服务器的时钟、私钥权限、服务身份认证和审计由部署方维护；本工具并不赋予任意本地运行实例“官方”身份。

新增专项调用真实 Rust 可执行文件与合成签发密钥，检查完整签发/核验、错公钥、错机构、有效期策略拒绝、证书字节变更、输出不覆盖、编号更新及不创建记录服务状态。正式机构接口、密钥托管、吊销和实时挑战仍未接入。

### 服务端无证书落盘通道

新增 `issue-stdin ISSUER_ID TTL_SECONDS ABSOLUTE_PRIVATE_SEED_HEX_FILE`：从标准输入读取最多 32 MiB 证书原字节，标准输出只返回回执 JSON，不创建证书、回执或采集服务文件。签发者、有效期和私钥路径只能由后续受控服务配置提供，不能从上传正文提取。错误输入不输出成功回执，命令行参数中不含私钥值。

机构接入仍应复用公共进程调用边界、权限和审计，限制并发、处理时间与返回大小，并清理子进程继承的数据库/JWT 等服务环境。此通道消除中转临时文件，不表示 HTTP 签发接口、授权、审计和密钥托管已实现。新增真实进程检查验证 stdout 回执可被独立核验、目录未变化及无效输入不输出回执，结果以相应新流程确认。

## 规则有效性验收要求，尚未完成

当前 `heuristic-2026-11-06.1` 是明确阈值的过程提醒，真实中英文课程作业尚未校准。正常粘贴、导入、语音、辅助输入、代码补全、宿主轮询及脚本模拟必须进入评估范围。大段写入本身不能被标记为 AI 创作。

评估应使用经授权并有来源依据的真实过程，按作者、文档及任务划分独立测试集，防止同一来源同时参与调参和验收。中文、英文、混合语言、不同宿主和输入方式应分别报告样本量、误报率、漏报率及置信区间，明确正负类定义与不适用范围。启发式单元测试和合成签名样本只能验证程序行为，不能替代有效性研究。AI 文本检测模型的基准也不能替代编辑过程规则的校准。

报告需保留规则与阈值版本、模型及数据版本、评估方法、校准适用范围和可复核原始统计；版本变更须重新评估。低样本、分布变化或未知来源不输出百分比确定性。参考 [NIST AI RMF](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=936225)。
