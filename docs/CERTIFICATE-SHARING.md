# 签名证书的分享与复核

核验页现在按“作品 → 证书 → 核验与分享”引导操作；证书标题、文件名、数据与说明增大字号，继续复用管理端的颜色、按钮和面板。

分享的可信载体是刚刚核验过的 `.wproof` 原始字节，而不是图片。浏览器支持文件分享时调用系统分享；否则下载原证书。另行发送作品原文件，接收方才能重新计算文件指纹。图片与 PDF 仅用于展示。

证书指纹定义为 `lowercase_hex(SHA-256(hex_decode(signature)))`。只在 Rust 核验签名有效后计算，完整证书与同一签名的部分披露证书得到相同指纹；它标识签名清单，不代表披露范围或字节格式相同。指纹不改变 v1/v2/v3 的签名协议。浏览器使用 Web Crypto，静态核验站点需要 HTTPS 或浏览器认可的本机安全来源。

接收方可在开始核验前填写从可信渠道取得的指纹。格式错误或不匹配时，即便文件和自签名本身有效，整体核验也不会通过，且不开放分享与图片导出。更换作品或填写指纹会使旧结果立即失效。攻击者若能同时替换证书和可信渠道中的指纹，仍能误导接收方；这不是身份认证服务。

完整证书含过程记录。页面提示可先导出部分证据并重新核验，再分享。部分证书仍含清单元数据；不能称为零知识或完整链核验。系统分享支持程度依赖浏览器，取消分享不会下载替代文件；剪贴板不可用时可手动复制完整指纹。

本轮不生成无法供别人访问的 localhost 分享链接，也未部署公网证书托管。证书被修改将导致签名或内容检查失败；整个证书被另一个密钥替换，需要独立取得的指纹才能识别。界面不承诺“100% 人类创作”或绝对不可伪造的作者身份。

验证由 GitHub Actions 运行真实 Wasm 浏览器测试，包括独立 Node SHA-256 对照、有效证书遇到错误指纹时失败、正确指纹通过、原字节下载、部分披露指纹保持一致与手机字号/溢出检查。本地不构建、不运行这些测试。
